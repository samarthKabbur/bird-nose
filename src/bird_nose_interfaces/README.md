# bird_nose_interfaces

## Purpose

Bird Nose's own ROS messages and actions. They are the contract between the packages: the survey, recorder, detector, direction finder, localizer, and evaluator only ever talk to each other through these types, so one package can be replaced without touching the others.

Package type: `ament_cmake` (interfaces generated by `rosidl`). It contains definitions only, no code.

## Contents

| File | Used for | Published by → used by |
| --- | --- | --- |
| `msg/SurveyEvent.msg` | Survey progress: started, arrived, failed, recorded, finished | `survey` → `evaluate_run`, operators |
| `msg/AudioChunk.msg` | About 100 ms of interleaved audio from every microphone channel | `sim_mic_array` or the capture driver → `recorder` (step 4.2) |
| `msg/Sample.msg` | One recording at a stop; the audio itself is a WAV file | `recorder` → `detector`, `doa` (4.2) |
| `msg/Detection.msg` | One species found in a sample | `detector` → `doa`, `localizer` (4.3) |
| `msg/BearingEstimate.msg` | Direction to a detected call, in the map frame | `doa` → `localizer` (4.4) |
| `msg/SourceEstimate.msg`, `msg/SourceEstimateArray.msg` | Candidate locations of calling birds, with uncertainty | `localizer` → reporting, evaluation (4.4) |
| `action/RecordSample.action` | Ask the recorder to record at the current stop | `survey` → `recorder` (4.2) |

Every field has a comment giving its units and frame; `ros2 interface show` prints them.

## Usage

```bash
ros2 interface list | grep bird_nose
ros2 interface show bird_nose_interfaces/msg/SurveyEvent
ros2 topic echo /Nuvo_7100VTC_Series/bird_nose/survey_events
```

In Python: `from bird_nose_interfaces.msg import SurveyEvent`, and add `<exec_depend>bird_nose_interfaces</exec_depend>` to the package's `package.xml`.

## Interfaces

Topics using these types sit under the robot namespace: `bird_nose/survey_events`, `bird_nose/audio`, `bird_nose/samples`, `bird_nose/detections`, `bird_nose/bearings`, `bird_nose/sources`. Only `bird_nose/survey_events` is published so far.

## Configuration

None.

## Testing

`colcon build --packages-select bird_nose_interfaces` checks every definition; CI builds it on every pull request. The packages that use the types test the behaviour.

## Limitations

- Defined ahead of use: only `SurveyEvent` has a publisher yet. The rest follow the Phase 4 design and may still change, in their own pull request, before the step that first uses them.
- Changing a field is a contract change: update every package that uses it in the same pull request, and record recordings made with the old definition as incompatible.
